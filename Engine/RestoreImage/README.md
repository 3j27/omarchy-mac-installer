# Restore image helper

This Swift port lives with the installer and implements `omarchy-restore-image` without a Go runtime or third-party codec. It uses CryptoKit for HPKE, HKDF and authentication, CommonCrypto for AEA AES-CTR, Apple's Compression framework for LZFSE/LZVN, zlib for APFS zlib storage, and Apple's `aea` tool for full-image decoding. The authenticated range path retains six concurrent requests and avoids downloading the entire restore image.

The implementation and recipe format derive from [Eryk Wieliczko's macos-firmware-extract](https://github.com/erykwieliczko/macos-firmware-extract/tree/71b413af680edec1808a709cb7addfbde5c21cfc) (MIT). Original implementation copyright Eryk Wieliczko; Swift changes copyright Aurora Silicon contributors. The pinned reference imports the original production helper from installer revision `bae75007c3b6247e5a14a2f653c15693092a7841`. Development-only commands are intentionally absent.

Build and test on macOS with Xcode 26.2:

```sh
swift test --package-path Engine/RestoreImage
swift test --package-path Engine/RestoreImage -c release
swift build --package-path Engine/RestoreImage -c release
```

The command-line interface remains:

```sh
omarchy-restore-image INPUT_AEA INPUT_SHA256 OUTPUT_DMG
omarchy-restore-image firmware-ranges RECIPE RECIPE_SHA256 OUTPUT_DIR
omarchy-restore-image verify-stage1 FILE SHA256 SIZE
omarchy-restore-image capabilities
```

Exit 75 permits the caller's fully pinned whole-image fallback only after recipe admission and a remote/decode failure. Local admission, publication, cancellation and total-deadline failures exit 1. Usage errors exit 64. Outputs are staged privately and published without replacing an existing destination.

Tests use the unchanged J700 recipe and synthetic cross-language vectors generated by the pinned Go reference. The vectors cover HPKE, HKDF, AES-CTR, HMAC, all six APFS compression types, and an authenticated AEA root/cluster/segment chain. No private key or firmware from a real installation appears in these fixtures; the P-256 key is a disposable test key.

`Reference/generate.sh` fetches the pinned reference and regenerates the synthetic interoperability fixtures with Go. It creates a new disposable test key; regenerated HPKE bytes intentionally change. Go is only needed for this optional reference check, not to build or run the Swift helper.

`build.sh OUTPUT_DIRECTORY` performs two clean release builds using the same toolchain, requires byte identity, and writes the executable plus a source/toolchain/digest manifest. The engine's source lock records those inputs and the resulting binary. This establishes repeatability on that recorded toolchain; it does not claim reproducibility across different Xcode versions.
